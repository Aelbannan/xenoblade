# Category D — Data architecture (`extern_data_sections`)

**Hand to:** one agent working with the repo owner (a policy decision is
required before mass changes). **Goal:** make data ownership explicit so the
295 `extern_data_sections` entries stop producing vacuous data matches and can
be retired. Prerequisite reading: `docs/handoff/unit_rules/README.md`.

## The situation

`extern_data_sections` (295 entries, 36 with no other field) does this: it
strips named data sections from the source-built object, sets their size to
zero, and converts their symbols to UNDEF so the link resolves them against
the shared retail data objects (`monolibdata*.o`, `nw4r_data.o`,
`criware_data.o`, …).

Two things follow:

1. The retail split object for those units has **no data** either, so
   `run.py data diff` compares empty-vs-empty and prints MATCH. Unit
   promotion (`NonMatching → Matching`) is supposed to require 100% code+data;
   for these units it does not.
2. The final DOL's data bytes for those units come from **retail objects**,
   not from `src/**`. That may be an acceptable project model (code-only
   matching while the shared data objects are still unmatched), but it is
   silent and currently double-counted as data matching.

This is not a per-unit byte bug like the rest of the table; it is a missing
architectural decision plus a gate that cannot see the difference.

## Task order

1. **Inventory (no decisions).** For every EDS unit:
   - which data symbols the source *defines* vs *declares*;
   - which shared object defines each (`config/<region>/splits.txt`,
     `configure.py` object list, `build/<region>/*.o` symbol tables);
   - the shared object's `configure.py` class (Matching / NonMatching /
     autogenerated);
   - any unit that both defines and strips data (the dangerous case).
   Write `docs/evidence/decomp/unit_rules_data_ownership.md`.
2. **Owner decision (blocking).** Record one of:
   - **(a) Code-only matching is supported.** Introduce an explicit unit
     kind/status (e.g. `MatchingCodeOnly`, or `Matching` + `dataOk=false`)
     and stop reporting stripped data as matched. EDS then becomes a
     mechanical link-composition rule with an honest label.
   - **(b) Every Matching unit owns its data.** Units that cannot match their
     data are demoted; EDS gets deleted and the source either defines real
     data or the unit is NonMatching.
   The decision goes into `PLAN.md` (progress definition + §17.6 posture).
3. **Source invariant.** For code-only units, foreign data must be
   `extern`-declared only. A TU that *defines* data owns it. Add a checker
   (extension of `data_match.py` or a small script) that flags a code-only
   unit defining symbols outside its declared ownership; run it in CI.
4. **Retire the rule.** With declarations-only enforced, MWCC naturally emits
   no data for the unit and `extern_data_sections` is redundant. Remove in
   batches (10-20 units), rebuilding and link-verifying each batch:
   - raw `data diff` still MATCH (empty vs empty);
   - no duplicate-symbol errors at link;
   - no change in linked bytes for unrelated units.
5. **Progress accounting.** Update `configure.py progress`,
   `tools/coop/readme_status.py`, `README.md`, and `docs/MWCC_CASES.md`'s
   data-TU sections so code-only units are visibly code-only. The headline
   percentage must not absorb them.

## Coordination

- Mixed entries (`CProc.o`, `CScn_80496B0C.o`, `lyt_pane.o#…`,
   `g3d_state.o`, `CView.o`, `CWorkThread.o`, `CTaskManager.o`, …) keep their
   EDS field until Category C removes the content fields; then D removes EDS.
- Never delete EDS from a unit whose source still defines the data: that
  duplicates symbols at link (the unit and the shared object both define
  them). The inventory in step 1 is what tells you which.
- Category B handles the non-EDS layout entries; do not touch those.

## Evidence / definition of done

- Decision recorded in `PLAN.md`; inventory doc written with per-unit
  ownership and the shared-object class.
- Unit kind/status implemented; progress/README report code-only units
  separately.
- Declarations-only checker in CI.
- All 295 EDS entries deleted (or converted to the explicit model) in
  link-verified batches; affected targets recertified from raw objects;
  `--claim`/`--ratchet` per batch.
- No vacuous data matches remain; the reported code+data percentage never
  counts a stripped unit.

**Report back:** owner decision, inventory summary, checker name, batches
(gone/left), link-verification evidence, and the before/after progress
numbers.
